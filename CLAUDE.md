# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Two separate sites in one folder

This is not one project with a subfolder — it is **two independent static sites** that must not be mixed:

| | Корневой лендинг | Платформа |
|---|---|---|
| Где | `index.html`, `css/`, `js/`, `assets/` | `site/` |
| Что это | Одностраничная презентация гранта (проблема → решение → бюджет → дорожная карта) | Многостраничный рабочий сайт: журнал, медиаархив, формы заявок, каталог зинов |
| Для кого | Грантодатель | Аудитория проекта |
| Своя документация | `README.md` | `site/README.md` |

Они **не делят ни строчки CSS или JS**: у платформы собственные `site/css/`, `site/js/`, `site/assets/`. Совпадение имён классов (`.card`, `.grid--2`, `.reveal`) — это две независимые реализации, а не общий код.

Заказчик отдельно просил лендинг не трогать. Правки в `index.html`, `css/style.css`, `css/reset.css`, `js/main.js` делать только по явной просьбе.

Папки `материалы/` (438 МБ исходных фото) и `реф/` (макет `07/Frame.png`, 1920×16200) — рабочие материалы, на хостинг не выгружаются.

## Запуск

Ни сборки, ни зависимостей. Но открыть файл двойным кликом нельзя: платформа построена на ES-модулях, браузер не запускает их с `file://`.

```bash
python3 -m http.server 8000        # из корня проекта
# http://localhost:8000/        — лендинг
# http://localhost:8000/site/   — платформа
```

Автотестов нет. Проверять — прогоном страниц в headless Chrome через CDP: ошибки консоли, битые ссылки, поведение форм и фильтров, вёрстка на 1440 и 390 px. Обязательно с отключённым кэшем (см. ловушки ниже).

## Архитектура платформы (`site/`)

### Контент живёт в одном месте

`site/js/data.js` — единственный источник данных: `regions`, `heroes`, `issues`, `materials`, `zines`, `contacts` плюс справочники `roleLabels` / `typeLabels` / `formatLabels`. Из него рендерятся карта, сетка выпусков, архив с фильтрами, досье героя, каталог зинов и выпадающий список в форме заказа. Добавление материала или выпуска — это правка одного массива, а не вёрстки.

Архив строится по `materials`, а не по `heroes`: пока согласия героев не подписаны, плашка «Герои» показывает пустое состояние, а в сетке лежат путевые заметки. `hero.html` работает, но из архива на него сейчас не ссылаются.

Исключения, сделанные намеренно: вопросы-ответы лежат прямо в `faq.html` (статичны, работают без JS), новости — в `news.html`, лонгрид — отдельный HTML-файл. У лонгрида уникальная композиция, из данных его рендерить нет смысла.

### Страницы собираются скриптом, но живут как обычный HTML

`site/_build/` — генератор: `shell.py` (общий `<head>`, шапка, футер), `pages_a.py` / `pages_b.py` / `notes.py` (тела страниц), `faq_data.py`, `privacy.py`, `build.py`.

```bash
cd site/_build && python3 build.py     # перезаписывает все 15 HTML-файлов
```

Скрипт нужен **только** чтобы поменять шапку, футер или `<head>` сразу везде. Обычные правки текста делаются прямо в готовых HTML. Если правили HTML руками — сначала перенесите изменения в `pages_*.py`, иначе сборка их сотрёт.

Там же лежит `artifact.py` — сборка всего сайта в один самодостаточный HTML (страницы в хеш-роутере, фото и шрифты внутри файла). Написан, но ни разу не запускался; к работе сайта отношения не имеет.

### Модули JS

Каждый модуль сам проверяет, есть ли на странице его разметка, и молча выходит. Поэтому `main.js` вызывает все инициализаторы подряд на любой странице.

- `ui.js` — общее: `photo()` (собирает `<picture>` с webp и запасным jpeg), `esc()`, `param()`, шапка, reveal
- `map.js` — карта, переиспользуется на главной и в архиве через `data-map-mode="link|filter"`; в режиме `filter` шлёт событие `map:select` вместо перехода
- `russia.js` — геометрия России: Natural Earth 110m (public domain), упрощена в систему координат 1000×460. Точки регионов — поля `x`/`y` в `data.js`, в той же системе. Детальный SVG подменяется здесь, остальной код не меняется
- `archive.js` — фильтры; состояние синхронизировано с query-строкой, чтобы ссылкой можно было делиться
- `forms.js`, `hero.js`, `issues.js` — см. ниже

### Формы

Все три формы (герой, участник, заказ зина) обслуживает один `forms.js`.

**`FORM_ENDPOINT` в начале файла — сейчас `null`.** В этом режиме формы валидируют, показывают экран «принято» и пишут payload в консоль, но никуда не отправляют. Пока строка не заполнена, сайт нельзя публиковать как принимающий заявки: человек увидит подтверждение, а заявка не придёт.

Что не сломать при правках:

- Блок `.guardian` разворачивается при возрасте < 18 и становится обязательным. Поля внутри закрытого блока исключаются из валидации функцией `activeFields()` — иначе форма для совершеннолетних не отправится.
- Разметка чекбокса: `.check` вложен в `.field`, а блок ошибки `.field__error` лежит в `.field`. Поиск контейнера идёт по `.field` намеренно — `closest('.field, .check')` находил бы `label` и текст ошибки пропадал.
- Загрузка файлов у Formspree работает только на платном тарифе, поэтому рядом всегда есть поле «ссылка на облако».

### Фотографии

```bash
python3 site/_build/photos.py          # из корня; --force пересобирает всё
```

Берёт оригиналы из `материалы/photo-source/`, кладёт в `site/assets/img/photo/` три ширины (2000/1200/600) в WebP плюс запасной JPEG на 1200, снимает EXIF (там GPS съёмки). Уже обработанные пропускает. Имя файла без расширения = `slug` для `data.js`; словарь `RENAME` даёт понятные имена вместо номеров с телефона.

Скрипт не растягивает кадры меньше целевой ширины, но запасной JPEG делает всегда — без него браузеры без WebP получают битую картинку.

Весь материал сейчас — Республика Алтай. Остальные пять регионов honest-состоянием показывают «экспедиция запланирована», выдуманных обложек нет.

Фотографии путевых заметок лежат под slug'ами `notes-01` … `notes-24` — нумерация повторяет порядок кадров в авторском тексте.

## Ловушки, на которые уже наступали

**`<picture>` не имеет собственной высоты.** Внутри контейнера с фиксированной пропорцией нужно `picture { display:block; width:100%; height:100% }`, иначе `height:100%` у `<img>` считается от auto, `object-fit: cover` не срабатывает и горизонтальные кадры не заполняют контейнер. Правила лежат в `components.css` (`.ph picture`) и `pages.css` (`.hero__media picture`).

**Уровни заголовков.** Карточки, которые идут сразу после `<h1>` без промежуточной секции, используют `<h2 class="card__title">`. Класс задаёт размер, тег — только структуру.

**Кэш Chrome при проверке.** Правки в JS и CSS не подхватываются, пока не отключён кэш. Проверять только с `Network.setCacheDisabled`, иначе легко решить, что исправление не сработало.

## Оформление

Палитра снята пипеткой с макета заказчика `реф/07/Frame.png` и живёт в `site/css/tokens.css`: графит `#2C2C2C`, карточки `#373737`, терракота `#B76E4A`, бумага `#F5EDE3`. Менять оформление — там, а не в компонентах.

Сквозной элемент из макета — кремовая бумажная записка со скрепкой (`.paper`, повёрнута на `-.6deg`). Используется для сносок, экранов подтверждения форм, реквизитов оплаты и врезок в лонгриде. Вторых метафор намеренно нет.

Шрифты Rubik и Inter лежат в `site/assets/fonts/` и раздаются со своего сервера: Google Fonts CDN в России работает нестабильно. `fonts.css` перечисляет `@font-face` с `unicode-range` — при добавлении начертания нужны и файл, и правило.

## Тон текстов

Кнопки называются по результату («Рассказать свою историю», а не «Отправить»). Пустые состояния и ошибки объясняют, что случилось и что делать дальше. Оценочных прилагательных вроде «уникальный» и «инновационный» нет — только факты, ровно так же, как проект говорит о людях.

Отдельно: в `data.js` карточки героев названы по кадру («Всадник с летнего выпаса»), а не по именам людей — интервью не расшифрованы и согласия не подписаны. Не заменяйте это на выдуманные имена и цитаты; места помечены `TODO`.
