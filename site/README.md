# Сайт-платформа проекта «ДРУГ»

Статический сайт: HTML, CSS и JavaScript без сборки и зависимостей.
Открывается на любом хостинге, куда можно положить файлы (GitHub Pages, Netlify,
обычный хостинг, Яндекс Облако).

Лендинг-презентация в корне проекта (`../index.html`) не тронут — это отдельный
документ для грантодателя. Когда захотите сделать платформу основным сайтом,
перенесите содержимое папки `site/` в корень.

---

## Как посмотреть локально

Из корня проекта:

```bash
python3 -m http.server 8000
```

Открыть <http://localhost:8000/site/>.

Просто дважды кликнуть по `index.html` не получится: браузер запрещает
ES-модулям работать с файловой системы. Нужен любой локальный сервер.

## 1. Куда приходят заявки

Приём заявок пока не подключён. Формы при этом **не обманывают**: они
проверяют поля, а потом показывают блок «Приём заявок ещё не подключён» —
с текстом заполненной заявки, кнопкой «Скопировать» и адресами почты
и Telegram. Человек уходит не с пустым обещанием ответа, а с заявкой в руках.

Чтобы заявки начали приходить сами:

1. Зарегистрируйтесь на сервисе приёма форм и создайте форму.
2. Скопируйте её адрес — он выглядит как `https://formspree.io/f/abcdwxyz`.
3. Откройте `_build/shell.py`, найдите строку

   ```python
   FORM_ENDPOINT = ''
   ```

   и впишите адрес:

   ```python
   FORM_ENDPOINT = 'https://formspree.io/f/abcdwxyz'
   ```

4. Пересоберите страницы:

   ```bash
   cd site/_build && python3 build.py
   ```

Всё. Три формы — герой, участник, заказ зина — начнут отправлять заявки на
вашу почту, а блок «не подключено» перестанет появляться. Тему письма каждая
форма подставляет свою, так что их легко разложить по папкам.

**Проверьте после подключения.** Отправьте по одной тестовой заявке каждой
из трёх форм и убедитесь, что письма дошли. Это единственная проверка,
которую нельзя сделать за вас.

**Где хранятся данные.** Если выберете зарубежный сервис приёма форм, заявки
россиян будут лежать на серверах за границей. По 152-ФЗ это отдельная история:
трансграничная передача и требование к местонахождению базы. Для проекта,
который собирает анкеты несовершеннолетних, это стоит обсудить с юристом
до запуска — либо взять российский сервис приёма форм.

**Про фотографии в форме героя.** Приём файлов у Formspree работает только на
платном тарифе. На бесплатном фотографии не дойдут — поэтому рядом с загрузкой
в форме есть поле «ссылка на облако». Если перейдёте на платный тариф,
переверстывать ничего не нужно, файлы поедут сами.

## 2. Как добавить выпуск, героя или зин

Всё это лежит в `js/data.js` — он подробно закомментирован. Общий порядок:

**Новый материал архива** — добавьте объект в массив `materials`. Обязательные
поля: `slug`, `type` (`territory`, `heroes` или `notes`), `region`, `formats`,
`title`, `lead`, `cover`, `url`, `date`. Карточка сама появится в архиве
и подхватится фильтрами.

**Новый герой** — добавьте объект в массив `heroes`. Обязательные поля:
`slug` (латиницей, без пробелов), `name`, `role`, `region`, `photo`, `gallery`.
Досье откроется по адресу `hero.html?slug=ваш-slug`. В открытой части архива
героев пока нет: пока не подписаны согласия, плашка «Герои» показывает
пустое состояние. Чтобы они появились в сетке, заведите на каждого запись
в `materials` с `type: 'heroes'`.

**Новый выпуск** — добавьте объект в `issues`. Пока лонгрида нет, оставьте
`published: false` и `url: null` — карточка покажется как «готовится», а с
`status: 'in-progress'` — как «выпуск в разработке» и не будет кликаться.
Когда лонгрид будет готов, поставьте `published: true` и укажите путь.

**Новый зин** — добавьте объект в `zines`. Он появится и в каталоге,
и в выпадающем списке формы заказа.

**Новости экспедиции** — правятся прямо в `news.html`: скопируйте блок
`<article class="news__item">` и вставьте сверху.

**Вопросы и ответы** — правятся прямо в `faq.html`.

### Места, помеченные TODO

В `data.js` карточки героев пока названы по кадру («Всадник с летнего выпаса»),
а не по имени человека: интервью не расшифрованы и согласия не подписаны.
Найдите в файле пометки `TODO` и замените на настоящие имена, цитаты и тексты,
когда они появятся.

## 3. Как добавить фотографии

Положите оригиналы в `материалы/photo-source/` и запустите из корня проекта:

```bash
python3 site/_build/photos.py
```

Скрипт сам сделает три размера (2000 / 1200 / 600 px), сожмёт в WebP,
положит запасной JPEG и вырежет EXIF — там хранятся GPS-координаты съёмки
и модель камеры, их не стоит публиковать.

Готовые файлы появятся в `assets/img/photo/` под именем файла-оригинала
без расширения. Это имя и есть `slug`, который вы указываете в `data.js`.

Кладите фотографии как есть, полноразмерные: скрипт уменьшит сам.

## 4. Как поменять оформление

Почти всё оформление собрано в `css/tokens.css`. Например, чтобы сменить
акцентный цвет, достаточно поправить одну строку:

```css
--accent: #B76E4A;   /* терракота */
```

Палитра снята пипеткой с исходного макета:
графит `#2C2C2C`, карточки `#373737`, терракота `#B76E4A`,
бумага `#F5EDE3`.

Шрифты — Rubik (заголовки) и Inter (текст), лежат в `assets/fonts/`
и раздаются с вашего сервера. Google Fonts не используется намеренно:
его CDN в России работает нестабильно.

## 6. Служебное: папка `_build`

Страницы собраны скриптом, чтобы шапка и футер были одинаковыми везде.
**Для обычной работы он не нужен** — правьте готовые HTML-файлы напрямую.

Скрипт пригодится, если надо поменять шапку, футер, `<head>` или адрес
приёма заявок сразу на всех пятнадцати страницах:

```bash
cd site/_build && python3 build.py
```

Он же перезаписывает `sitemap.xml` и `robots.txt`.

Рядом лежат ещё два служебных скрипта:

```bash
python3 _build/photos.py           # из корня проекта: готовит фотографии
python3 _build/fonts.py --check    # покажет, сколько весит латиница
python3 _build/fonts.py            # подрежет её (нужен fonttools)
```

`fonts.py` уже прогнан: латинские начертания подрезаны, 58 КБ с первой
загрузки. Повторный запуск ничего не испортит. Если скачаете начертание
заново с Google Fonts, прогоните скрипт ещё раз.

Внимание: сборка перезапишет все HTML-файлы. Если вы правили их руками,
сначала перенесите изменения в `_build/pages_a.py`, `_build/pages_b.py`
или `_build/notes.py`.
